Game Overview

You are a prisoner locked in a cell. First, find a hidden tool inside your cell to break out. Then navigate the prison — avoid AI-powered guards, collect 3 keycards, push barricades to reroute guards, and reach the exit gate. Guards use real pathfinding algorithms that adapt dynamically when you block their path.
CORE CONCEPT
  • 3D first-person stealth escape game
  • Player starts locked in a prison cell — must find a hidden tool to escape it first
  • Prison environment — corridors, cells, security room, exit gate
  • Collect 3 keycards spread across the prison to unlock the exit
  • Guards patrol and chase using AI pathfinding
  • Player can push barricades to reroute guards
WHAT MAKES IT SPECIAL
  • Guard AI uses real A* search algorithm (not scripted)
  • Environment is mathematically mapped as a graph
  • Blocking a corridor triggers live path recalculation
  • Debug mode lets you see AI paths drawn in-engine
  • Physics-based player interaction with doors & barricades

Game Flow

STEP-BY-STEP GAMEPLAY SEQUENCE
START → ESCAPE CELL → AVOID GUARDS → COLLECT KEYS → UNLOCK EXIT → ESCAPE
01
START — Locked in Prison Cell
Game begins. Player is locked inside a dimly lit prison cell. The cell door is shut. Guards are patrolling outside.
02
ESCAPE CELL — Find the Hidden Tool
Player searches the cell and finds a hidden tool (e.g. a lockpick or key). Use it to interact with the cell door and break out into the corridor. This is the first puzzle before any guard interaction.
03
AVOID GUARDS — Navigate the Corridors
Guards patrol corridors using A*-driven routes. Player must observe guard patterns, time their movement, and stay out of vision cones. Push barricades to block and reroute guards — the AI recalculates its path in real-time.
04
COLLECT KEYS — 3 Keycards Across the Prison
Keycard 1 — near starting corridor (low risk). Keycard 2 — inside the security room (moderate risk). Keycard 3 — deep in a guard patrol zone (high risk). Each requires careful timing and planning.
05
UNLOCK EXIT — Use All 3 Keycards
With all 3 keycards collected, approach the exit gate. Use the keycard reader to unlock it. The exit is heavily guarded — this is the most dangerous moment in the game.
06
ESCAPE — Pass Through the Exit Gate
Gate unlocked. Player passes through. Mission complete. If a guard catches you at any point — Game Over, restart from the beginning.
🏆
ESCAPE SUCCESSFUL
Or — if a guard catches you at any stage — Game Over. Restart from the beginning.

IS — Member Responsibilities

Each member is individually graded on their IS role via Git commits. The rubric evaluates Algorithm Accuracy (25%), Algorithmic Complexity understanding (25%), and Git & Code Quality (15%).
Student 1
CUSTOM GRAPH FORMULATION
CORE TASKS
  • Write script to extract NavMesh data into a graph
  • Generate nodes from walkable NavMesh positions
  • Build adjacency list with edge weights (distances)
  • Output graph to console — verifiable before 3D use
  • Optimise graph size — avoid redundant nodes
VIVA PREP — IS
  • How is the NavMesh converted to a graph?
  • Time complexity of adjacency list construction: O(V + E)
  • Why adjacency list over adjacency matrix here?
Student 2
DYNAMIC ADAPTATION & EVENT INTERCEPTION
CORE TASKS
  • Write event listener for barricade placement/collision
  • Detect which graph edges are blocked by barricade position
  • Sever those edges in the adjacency list in real-time
  • Trigger A* recalculation without causing infinite loops
  • Restore edges if barricade is removed
VIVA PREP — IS
  • How do you detect which edges to sever?
  • How is an infinite recalculation loop prevented?
  • What happens to the guard path mid-travel when edge is severed?
Student 3
A* SEARCH & HEURISTIC DESIGN
CORE TASKS
  • Implement A* algorithm using the graph from S1
  • Build a min-heap priority queue for open node selection
  • Define heuristic h(n) — Euclidean distance to goal
  • Ensure heuristic is admissible: h(n) ≤ actual cost
  • Print correct paths to console before 3D integration
VIVA PREP — IS
  • Explain f(n) = g(n) + h(n) formula
  • Why is Euclidean heuristic admissible here?
  • A* time complexity: O(E log V) with binary heap
Student 4
SECONDARY SEARCH & DEBUG VISUALIZER
CORE TASKS
  • Implement BFS algorithm on the same graph
  • Implement UCS (Uniform Cost Search) as alternative
  • Compare BFS / UCS paths vs A* paths in console
  • Build toggleable debug mode — draws nodes & paths in 3D view
  • Debug visualizer must not degrade game performance
VIVA PREP — IS
  • BFS complexity O(V + E) vs A* O(E log V) — why use A*?
  • What does UCS optimize that BFS doesn't?
  • How is the debug overlay drawn without impacting performance?
